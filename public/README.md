# Обзор продаж — интерактивная витрина

Статический дашборд без бэкенда: Python собирает витрину из сырых данных,
страница считает все срезы в браузере.

## Как устроено

```
build_data.py          сборка витрины: чистка → агрегация → сверка → JSON
public/
  index.html
  app.css
  app.js               свёртка таблицы фактов + SVG-графики без библиотек
  data/*.json          витрина, ~900 КБ
```

В браузер уезжает **одна таблица фактов** на зерне
`месяц × регион × сегмент × корзина скидки × товар × клиент` (9985 строк).
Все цифры на странице — свёртка этой таблицы: предпосчитанных агрегатов нет,
поэтому блоки не могут разойтись между собой.

## Сборка витрины

```bash
python3 build_data.py --src "data/Sample - Superstore.csv" --out public/data
```

Скрипт определяет формат даты по самим данным, протоколирует каждую
выброшенную строку и **падает с ошибкой**, если суммы витрины не сходятся
с исходником. Ключ `--keep-duplicates` оставляет полные дубликаты строк заказа.

## Запуск страницы

```bash
cd public && python3 -m http.server 8000
```

Затем http://localhost:8000 — открывать двойным кликом нельзя, `fetch`
не работает с `file://`.

## Публикация

GitHub Pages: содержимое `public/` в ветку `gh-pages` или папку `/docs`.
Firebase Hosting: `firebase init hosting` с `public` в качестве каталога,
дальше `firebase deploy`.

## Проверки

```bash
node test_rollup.mjs    # цифры
node test_render.mjs    # отрисовка
```

`test_rollup` сверяет свёртку с эталонными числами из Python: итоги по годам,
разрезы по регионам, суммы по всем измерениям, работу фильтра.

`test_render` прогоняет весь путь `render()` на заглушке DOM во всех
комбинациях периода, метрики и фильтра — ловит ошибки в графиках
до открытия браузера.

## Оформление

Вся палитра и шрифты — CSS-переменные в начале `app.css`. Акцентный цвет
`--accent` используется и как цвет убытка на графиках: смена одной строки
перекрашивает разворот целиком. Калибровка (contrast ratio к `--paper`,
разделение по светлоте, симуляция дальтонизма) проверена расчётом — `--rev-soft`
и `--prior` были почти нечитаемы на бумаге (1.6–1.8:1), пересчитаны до ≥3.3:1.

## Известные доработки

- Таблица фактов больше не хранит `orders` как столбец: `nunique(order_id)`
  на её зерне задваивал заказы с несколькими товарными позициями (было 3310
  вместо 1687 за 2017 год). Количество заказов теперь считает `orders.json` —
  отдельный справочник на зерне месяц/регион/сегмент/клиент.
- Блоки «Каналы», «Товары», «Клиенты» дорисованы поверх уже готовой витрины:
  фильтры по каналу/скидке/подкатегории работают сквозь весь разворот так же,
  как фильтр по региону (`scan()` принимает `ignore: [...]`, чтобы каждый
  блок не фильтровал сам себя).
- Анимации (появление баров, count-up KPI) теперь проигрываются только при
  первой загрузке страницы, а не при каждом клике по фильтру.
